# بيانات مكتبة قلم

مستودع مستقل لفهرس البيانات النصية وأدوات استيرادها، منفصل عن مستودع التطبيق وعن منصة قلم.

ملفات PDF الأصلية محفوظة في مجلدات Google Drive المجهزة للمكتبة، لا في GitHub. لا ترفع مفاتيح الخدمة أو بيانات الحسابات أو ملفات PDF هنا.

سيُحفظ هنا مخطط الفهرس، بيانات تعريف الوثائق العامة، وأدوات بناء/تحديث قاعدة SQLite النصية. قاعدة التشغيل لا تُنشر إلى GitHub إن تجاوزت حدود الحجم؛ تخزن في Drive وتُنقل إلى Render أثناء التجهيز أو تُخزن في MongoDB بعد تحويلها.

## رصد Drive اليومي

يوجد سير عمل GitHub Actions يومي (`.github/workflows/drive-monitor.yml`) يفحص ملفات PDF أسفل مجلد Drive الجذري الذي تحدده. أول تشغيل ينشئ خط أساس ولا يعالج الأرشيف القديم. بعد ذلك يلخص الملفات الجديدة والمتغيرة والمحذوفة في سجل التشغيل. هذه المرحلة للقراءة والرصد فقط: لا تنزّل الملفات، ولا تشغّل OCR، ولا تعدّل Drive أو تنشر نصوصاً في المكتبة.

المجلد الجذري المحدد هو مجلد `الأصول` الذي يضم المواد القانونية والمؤسسات والاجتهادات والاتفاقيات والأبحاث. لتفعيل الفحص، أنشئ حساب خدمة في مشروع Google Cloud مستقل للمكتبة، وفعّل Google Drive API، ثم شارك معه مجلد `الأصول` بصلاحية **مشاهد** فقط. لا تمنحه صلاحية على بقية Drive. أضف محتوى ملف JSON الخاص بحساب الخدمة كاملاً إلى أسرار مستودع `Qalam-Library-data` تحت **Settings → Secrets and variables → Actions**:

- `GOOGLE_SERVICE_ACCOUNT_JSON`

يستخدم الفحص نطاق القراءة الوصفية `drive.metadata.readonly` فقط؛ لا يستطيع تنزيل PDF أو تغيير Drive. لا تستخدم مفتاح API لهذا الوصول ولا تضع ملف JSON في المستودع. شغّل الفحص يدوياً أول مرة من **Actions → Daily Google Drive monitor → Run workflow**؛ بعد ذلك يعمل يومياً عند 02:17 UTC.

يُحفظ خط الأساس في `state/drive-sync.json`، ويُسجل كل تغيير من دون رقم ملف Drive الخام. إذا أزيل ملف من Drive، يذكره التقرير فقط ولا يحذف أي نص من المكتبة. معالجة OCR والاستيراد إلى قائمة المراجعة خطوة لاحقة منفصلة.
